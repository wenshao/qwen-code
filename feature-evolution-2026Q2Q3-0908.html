多客户端→常驻 Daemon→Workspace Runtime→ACP 子进程→模型 / 工具

关键差异：CLI 只是多个入口之一。会话路由、workspace 选择、事件流、恢复协调和横切服务由独立控制面承接，因此 Web、桌面、IDE、Channel 与 SDK 可以围绕同一后端协作。

Claude Code / Codex · 默认本地 CLI 路径process-centered
Terminal / IDE→当前 CLI 进程→本地仓库 / 命令↔模型服务

默认交互中心是当前启动的 CLI：它读取和修改本地仓库、运行命令，并保存/恢复自己的会话。官方公开页面没有把常驻本地 daemon 描述为默认的多客户端会话中枢。

不要混为一谈：Claude Code IDE 扩展会启动其私有 CLI，并以本地 MCP 连接外部 CLI；Codex Cloud 则在隔离云环境后台运行任务。两者都是扩展路径，不等价于本图中的本地 Daemon 控制面。
公开资料口径：Claude Code Overview · Claude Code IDE Integrations · Codex CLI · Codex Cloud。竞品架构仅描述官方文档明确支持的默认路径，不排除未公开实现或后续演进。
开放协议 · Open Protocols

开放协议骨架：ACP / MCP / CDP 把多端与生态连成一体

协议相关合入提交 · ACP 140 / MCP 117 / CDP 2

若 core+daemon 是引擎，开放协议就是把它接到外部世界的神经束。本季度 ACP 从 daemon 内部协议长成多客户端开放标准（stdio → SSE → Streamable HTTP → WS+REST，29 方法 + 控制请求 + 权限协调），MCP 从"能连工具服务器"长成带 OAuth、热重载、传输池与运行时增删的工具 / 资源生态，CDP 与 A2A 则把浏览器与 agent 间互联也纳入版图。季度末（08-24 起）继续向治理与韧性加深：ACP 通道传输存活性、托管记忆生命周期接入与子进程树回收，MCP 重启 server 会话内恢复、工具参数送入 AUTO 分类器，hooks 信任边界收口。左为协议栈实况，编号对应右侧能力清单；悬停联动高亮。
