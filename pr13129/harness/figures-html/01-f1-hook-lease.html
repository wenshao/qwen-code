Mechanism. HostedHookSession acquires its broker hooks-<randomUUID> on the first Hook and releases it only in close(); the lease row names that Runtime Session while A is idle (hooks-ad882e49-1cd1-44f7-95c8-4833d212dabd). A new Harness builds a new random broker and adopts old owners only for unresolved executions, so the settled owner is never released — unlike HostedMcpSession, which reuses its recorded owner. The Broker accepts tool-sessions/<old>:release from the new Harness (200 released:true, idempotent), which is what candidate v2 does on ensureReady().
