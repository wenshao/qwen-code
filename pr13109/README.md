# PR 13109 real-stack verification: evidence

Head `cb322eedc3`, base `7827a3ffcd` (merge base). See `results/artifacts.txt` for hashes and environments.

- `01`–`04-*.png`: cards generated by `harness/gen-figs.mjs` from the `RESULT` lines below (no number is typed by hand).
- `results/summary.txt`: every scenario in compact form. `B` = request seen by the Broker proxy, `S` = MCP configuration record commit seen by the store proxy, `!label` = injected fault.
- `results/<rig>/<scenario>.log`: raw `RESULT` line per run; `results/<rig>/ledgers/`: raw Broker and store ledgers.
  - `head`, `base`: macOS, MySQL 8.4.11, one Spring (store + embedded Broker) per build. `cand-*` in `head` = the candidate CLI as the Harness.
  - `maria`: PR head on MariaDB 10.11.18. `merge` and `merge2`: Java from the test merges with main `ed95678747` and `78143fe335`, CLI from the PR head.
  - `skew2`: PR Broker in one Spring, a store-only Spring from the base build on the same database, later replaced by the PR build.
  - `skew`: first attempt with store and Broker in one Spring; the restart also restarted the Broker, so it only shows the non-durable restart behaviour.
  - `lx-*`: Linux container, durable local workers. `lx-head-r8`, `lx-base`, `lx-cand`: Broker restart scenarios (`r8-*`). `lx-head`: release scenarios on Linux.
- `results/mutants.txt`: 25 mutants of the PR's production lines; failing test names per mutant. `BASE1`/`BASE2` are unmutated runs.
- `candidate/`: the retry suggested in review thread R1-1 plus two unit tests (`candidate-r1-1-and-tests.patch`, applies to the PR head and to the test merge), unit results for three arms, `tsc` result.
- `harness/`: the rig. `up.sh` starts MCP fixture servers, the manifest and Spring (`java/RigMain.java`); `run.sh` runs one scenario (`r1`–`r8`) from a built tree; `lib.ts` holds the Broker proxy, the store proxy and the Harness launcher; `lx/` is the container variant (drivers are bundled with esbuild, the Broker runs with durable local workers).

Scenario files: `r1-release` (faults on the release path), `r2-sticky` (stdout held past the drain bound), `r3-upgrade` (records written by the base Harness, then loaded by the PR Harness), `r4-never-dispatched`, `r5-skew`, `r6-http-down`, `r7-drained-window`, `r8-broker-restart`. `s1c`, `s9`, `s20` are regression scenarios carried over from the #12946 rounds.

Local paths in logs are rewritten to `/rig-host`.
