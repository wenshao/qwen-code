Put together: a background Shell started in a turn is terminated when that same turn finishes — "keeps running after this result" lasts until the turn's own release, seconds later. Before 04ea968dc8 the Broker refused that release busy, and by code finish() turns a failed release into HostedToolRecoveryRequiredError, so neither version lets the turn end normally with the Shell alive. The Runtime Session is per turn while the Shell is meant to outlive it.
Also: the drain goes through the full transport.release, whose provider "release" closes the worker's admission for that Runtime Session before the activation drain runs. If the drain cannot prove its stops (409, swallowed), the Broker still answers busy but the worker side is already closed.
