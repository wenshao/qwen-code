No sequence of real worker answers lets the Broker settle a Shell that ended on its own: shell-status can only say "running" or "unknown", and the Broker never asks: neither shell-status nor shell-terminate has a production sender. Once child_run is enabled, every background start would leave a PREPARED ":process" row — and with it the Runtime hold (hasActiveBy*) — that nothing in this PR settles; after the Shell exits, workspace close (workspace_close_execution_unsettled) and Session release would stay blocked. The Java test passes because its double answers a state the worker never sends.
